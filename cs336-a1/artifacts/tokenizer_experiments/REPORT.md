## (d) 全量编码与 uint16

输出为小端 uint16 原始 NumPy 数据（.bin），保留原换行及文档分隔 token。
每批在特殊 token 后切分并校验解码还原；有界任务队列按原文顺序写盘。
中断后重跑同一命令，从已持久化的字节偏移继续；不要同时启动两个写同一输出的任务。

uint16 范围为0～65535，覆盖本实验10K/32K词表的全部ID；每ID仅2字节，比int64节省75%的数组存储空间。转换前检查整个词表ID范围。

### 1. 为什么 uint16 合适？
token ID 是非负整数，我们的词表大小是 10,000 和 32,000，对应的 ID 都在 0～65535 范围内。
uint16 恰好能表示这个范围，而且每个 ID 只占 2 字节：
类型	每个 ID 占用	是否适合当前词表
uint8	1 字节	不够，最大只能表示 255
uint16	2 字节	足够
int64	8 字节	足够，但占用更多空间


因此，使用 uint16 比 int64 节省 75% 的数组存储空间，也减少了读写的数据量。保存前要检查实际 ID 范围。
